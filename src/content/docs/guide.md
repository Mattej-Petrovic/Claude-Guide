This guide is for people who already use Claude and want to go deeper. If you're trying to figure out what Claude is, start with Anthropic's docs at [docs.claude.com](https://docs.claude.com) — they'll get you there faster than anything written here.

The guide is organized into seven sections. Foundations is roughly sequential; everything else is reference. Read what you need, skip what you don't.

## The seven sections

**Foundations** — the shape of the Claude ecosystem. What exists, which model to use when, which product fits which job. Start here if you're new to the broader picture.

**Products** — one page per Claude product. What it's for, how it actually gets used, where it falls short.

**Concepts** — the ideas that show up across products. Memory, projects, artifacts, subagents, hooks. If you keep seeing a word and don't fully know what it means, it's probably here.

**Extending** — how to make Claude do more than it does out of the box. Skills, MCP, connectors, plugins, commands. The line between "user" and "builder" lives in this section.

**Workflows** — how people actually use Claude day to day. Token optimization, prompting patterns, specific setups that work.

**Library** — cheatsheets. Lists of commands, skills, plugins, MCP servers worth knowing about. Terse on purpose. Not tutorials.

**Settings** — the parts of the interface most people never touch. Customization, usage limits, what each toggle actually does.

## A note on reference pages

The Library section is different from the rest. Those pages are scannable lists — no pedagogy, no rhythm, no "how to use it well" beat. If you land on one and it feels stripped down, that's by design. Concept and product pages teach. Library pages remind.

## What this guide isn't

Not a rewording of Anthropic's docs. Where they cover something well, this guide links out and adds the practitioner depth on top — what works, what doesn't, what most people miss. If a page reads like a manual, it's failing. Tell me.
